## 1. 프로젝트 개요

- **공연**: 라이브 융복합 퍼포먼스 ⟨매듭: 신윤복을 엮다⟩. 신윤복 풍속화 10점(혜원전신첩) + 미인도를 타블로 비방·실시간 폴리·라이브 비주얼로 재해석하는 넌버벌 공연. 2025.9 서울예대 쇼케이스 완료, **2026.9 뉴욕 La MaMa 본공연 예정**. 사용자(Kim)는 작가이자 드라마트루기. 연출 김지영 교수, 안무 김소이 교수.
- **논문 이력 (중요)**:
  - ❌ **AI 활용 사례 연구 논문은 폐기됨** (`소논문_매듭_신윤복을_엮다_AI활용사례연구.docx`가 outputs에 잔존할 수 있으나 사용하지 않음).
  - ✅ **현행 논문**: `소논문_매듭_넌버벌대본작성방법론.docx` — AI 언급을 전부 제거하고 '넌버벌 퍼포먼스 대본 작성 방법론'으로 전면 각색한 것. 이 논문만 수정 대상이다.

## 2. 현행 논문 상태

- **제목**: 「조선 풍속화의 시각 정보를 넌버벌 퍼포먼스 서사로 변환하는 대본 작성 방법론 연구 — ⟨매듭: 신윤복을 엮다⟩의 개고 과정을 중심으로」 (심사자 1안 채택. 2안 "회화 기반 넌버벌 퍼포먼스 대본의 작성 및 개고 방법론"은 학술지 투고용 대안)
- **분량**: 24페이지. 본문(초록·Abstract·1~6장) + 참고문헌 11건 + 부록 1(버전 대조표)·부록 2(창작 기준 문서 발췌)
- **구조**: 1장 서론(1.1 배경 / 1.2 장르적 특수성·넌버벌 범위 규정 / 1.3 연구 대상·세계 진입 2단계 / 1.4 미술사적 이해 / 1.5 선행연구·갭 / 1.6 연구질문 4개) → 2장 연구 방법(2.1 4시기·집중 대조 4텍스트 / 2.2 창작 기준 문서 / 2.3 분석 절차 5단계 / 2.4 practice-led·이중 위치) → 3장 시각 정보 변환(3.1 쌍륙삼매 등장 순서 고찰+그림 1 / 3.2 월하정인 의식적 변형 / 3.3 항목화) → 4장 문체 방법론(표 1 서술 기준 / 4.1 네거티브 샘플 3사례 / 4.2 필체 원칙 산문화 / 4.3 기물 명칭 예외) → 5장 개고 분석(5.1 분기 설계 / 5.2 표 2 검증 7건 / 5.2.1 전모 / 5.2.2 쌍육삼매 표기 / 5.3 감정 아크 잠정 원칙) → 6장 결론(4원칙 + 브리콜라주 수미상관)
- **형식 요소**: 페이지 번호(하단 중앙), `[저자명] ([소속])` 자리 표시(사용자가 직접 기입), 영문 제목·Abstract·Keywords, 표 1·표 2 캡션, 그림 1(쌍륙삼매 원화, 간송미술관 소장 캡션)
- **직전 작업**: 상세 심사 의견 19개 항목 전수 반영 완료 (아래 8절)

## 3. 빌드 시스템 (수정 작업 방법)

논문은 docx 라이브러리(Node.js) 스크립트 3개로 생성된다. **소스는 `/mnt/user-data/outputs/논문빌드소스/`에 백업되어 있다** (`/home/claude`는 채팅마다 초기화되므로 반드시 백업본에서 시작할 것).

```bash
# 1) 소스를 작업 디렉토리로 복사
cp /mnt/user-data/outputs/논문빌드소스/method_part*.js /home/claude/
# 2) 수정 후 빌드 (part2가 빌더를 포함)
cd /home/claude && node method_part2.js
# 3) 검증
python /mnt/skills/public/docx/scripts/office/validate.py /mnt/user-data/outputs/소논문_매듭_넌버벌대본작성방법론.docx
# 4) 분량·렌더링 확인
python /mnt/skills/public/docx/scripts/office/soffice.py --headless --convert-to pdf /mnt/user-data/outputs/소논문_매듭_넌버벌대본작성방법론.docx --outdir /tmp/
```

- `method_part1.js`: 헬퍼 함수(h1/h2/h3/p/q/caption), **각주 정의 전체(1~18)**, 제목부·초록·Abstract·1장·2장
- `method_part2.js`: 3~6장, 참고문헌, 표 1·2, 그림 1 삽입, 페이지 번호 footer, 문서 빌더
- `method_part3.js`: 부록 1(대조표), 부록 2(창작 기준 문서 발췌)
- 본문 문단은 `p("...")` 또는 각주 포함 시 `p(["...텍스트", 각주번호, " 이어지는 텍스트"])` 세그먼트 배열
- **수정 후에는 반드시 소스 백업본도 갱신할 것**: `cp /home/claude/method_part*.js /mnt/user-data/outputs/논문빌드소스/`

## 6. 집필 원칙 (이 논문의 정체성 — 위반 금지)

이 논문은 AI 활용 흔적을 제거하고 작가의 방법론으로 각색한 것이다. 다음 원칙이 문장 단위로 지켜져야 한다.

1. **판단·아이디어·원칙 = 작가 능동태**: "~하기로 판단했다", "~를 택했다" (전부 실제로 작가의 판단이므로 사실)
2. **발견·확인 과정 = 무주체 서술**: "~이 확인되었다", "~이 드러났다". 발견 주체를 작가로 허위 귀속하는 문장은 쓰지 않는다.
3. **금지 용어 (전무 상태 유지)**: AI, LLM, Claude, 스킬, 환각, RAG, 생성형, 프롬프트. 수정 후 PDF 전문 검색으로 잔존 0회를 확인할 것.
4. **기계적 어감 금지**: "등록되었다", "수칙" 같은 시스템 냄새 나는 표현 대신 사람의 작업 언어를 쓴다. 예: "아까운 마음을 접고 창작 메모의 금지 목록에 옮겨 적어 두었다."
5. **용어 확정**: '창작 수칙' → **'창작 메모'** (전량 교체 완료. 절대 되돌리지 말 것). 문서 3종 명칭: 원화 정보 문서 / 창작 메모 / 표현 패턴 기록 (총칭: 창작 기준 문서). 스킬 파일명(SKILL.md, paintings.md 등)은 본문·부록 어디에도 쓰지 않는다.
6. **작가의 실수로 읽힐 서술 금지**: 쌍륙삼매 사례는 "기억 의존 착오" 프레임이 아니라 **"등장 순서에 대한 고찰"**(전원 동시 등장 vs 일부 합류) 프레임으로 서술한다.

## 7. 확정된 사실 관계 (틀리기 쉬운 것 — 실물 검증 완료)

- **'260404 주유청강VER' = 전통 소녀 등장** (실제 대본에서 59회 출현 확인) / **'무녀신무VER' = 전통 소녀 미등장** (0회). ⚠️ 과거 기록·기억이 반대로 남아 있을 수 있으니 이 실물 검증 결과가 정답이다.
- **최종 채택 = 전통 소녀 없는 버전**. 분기 이유: "그림을 재현하는 퍼포먼스에서 한 사람에게 이목이 집중되는 것이 맞는가"라는 제작 논의. '260406' 통합은 전통 소녀 없는 구성 기반.
- **오늘의 소녀 세계 진입 2단계**: 청루소일 막간극 = 공간의 진입(도구를 내려놓고 세계 안으로) / 미인도 = 정체의 전환(그림의 주인공). 이 구분은 1.3, 5.3, 부록 2.1에 일관 적용됨.
- **쌍육삼매(그림 정식 제목) / 쌍륙(놀이 표준어)**: 의도된 표기 구분. 통일하라는 제안은 기각된 이력이 있음(5.2.2).
- **쌍륙삼매 원화**: 야외 배경, 남녀 합계 4인 (여인 2인 + 담뱃대 든 남자 + 갓 쓴 남성).
- **전모 소녀**: 구 명칭 '어우동 소녀'(작업 통칭) → '전모(氈帽) 소녀'로 교체. 넌버벌은 이름이 불리지 않아 작업 통칭이 자연 발생한다는 프레임(5.2.1).
- **버전 계보**: 최초 초고~'260328'(양식 확립기, 3차 개고) → '260404' 2종(복수 버전기) → '260406'(통합기) → '260411'(검증·완성기, 현행본). 집중 대조는 4텍스트('260328', '260404' 2종, '260411')로 한정 명시.
- 미디어 데스크(○) / 미디어 테이블(× 폐기 표기). 기물 명칭은 연출 서술 배제 원칙의 의도된 예외(4.3).

## 10. 스타일 규칙 (기존 확정 사항)

- 엠대시 연결 금지, 본문은 Arial 11pt(size 22) 현재형 학술 산문
- 버전명은 홑따옴표: '260328', '260404 주유청강VER'
- 대본 인용은 q() 블록(좌측 회색 선), 표는 cell/caption 헬퍼 사용
- 각주는 MLA 주석 형식(최초 전체 서지, 재인용 축약)
- 부록은 본문 절 번호를 역참조("본문 3.1에서 논의한…")
- 수정 후 체크: validate.py 통과 → PDF 변환 → 분량 확인 → 금지 용어 0회 → 각주 정렬 확인
